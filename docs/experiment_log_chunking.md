# 이슈 #22 - 의미 단위 청킹 실험 기록

## 배경

기존 청킹은 문서 전체를 800자로 잘라 절 경계를 무시한다. `1 사업개요` 끝과 `2 추진배경` 앞이 한 청크에
섞이고, 청크만 봐서는 어느 항목인지 알 수 없다.

이슈 #84에서 이미지 청크 첫 줄에 유형·요약을 세운 뒤 Q13의 정답 키워드가 1.0/3에서 2.3/3으로 오른 것을
확인했다. 본문에도 같은 원리가 통하는지, 절 제목을 붙이면 검색이 좋아지는지 실측했다.

## 절 경계를 어떻게 아는가

HWP는 장·절 제목을 1행짜리 표로 만든다. 이슈 #84에서 표 청크 대상이 아닌 표(`layout_table` 2,479개)로
분류해 본문에 남기고 있던 것이 바로 이 제목 상자다. 정규식으로 제목 패턴을 추측할 필요가 없다.

```
doc_001 표1   2024년 특성화 맞춤형 교육환경 구축 ... 제안요청서   1행 1열
doc_001 표3   Ⅰ 사업 안내                                      1행 3열
doc_001 표4   1 사업개요                                       1행 4열
```

문서 96건 전부에서 경계가 잡혔다. 다만 조직도나 실적표도 1행 표로 만드는 문서가 있어, 제목으로 쓸지는
글자 수로 구른다(`max_section_title_length: 40`). 긴 것은 경계로만 쓰고 본문에 이어 붙인다.

## 비교한 4세트

| 세트 | 청크 수 | 구성 |
| :--- | ---: | :--- |
| 기존 | 10,222 | 본문만. 표는 구분자 없이 뭉개짐, 이미지 없음 |
| 추출 | 17,382 | 본문 + 표 + 이미지 (이슈 #84 결과) |
| 제목 | 18,518 | 추출 + 절 경계 존중 + 본문 청크에 절 제목 |
| 표머리 | 18,518 | 제목 + 표 청크 첫 줄에 `[기관명 · 사업명]` |

네 세트를 같은 임베딩 모델(`text-embedding-3-small`)로 각각 색인해 조건을 맞췄다.
생성은 `gpt-5-nano`가 비결정적이라 문항마다 3회 반복해 평균을 냈다.

## 절 제목의 효과

키워드 적중률이 62.0%에서 74.4%로 올랐다. 표·이미지를 넣어 얻은 폭(+1.7%p)보다 크다.

- **Q07(다문서 비교)** 2.0/4 → 4.0/4. 기존과 추출 양쪽에서 움직이지 않던 문항이다.
- **Q09(후속 질문)** 0.0/2 → 2.0/2. 표 청크가 본문을 밀어내 깨졌던 것이 복구됐다.
  표 점유가 2.6에서 2.4로 줄었다. 제목이 붙어 본문 청크의 검색 신호가 강해진 결과로 보인다.
- **Q13(이미지)** 1.7/3 → 2.7/3.

Q09가 특히 의미가 있다. 이슈 #84에서 `top_k` 조정이 필요하다고 Retrieval에 넘기려던 문제인데,
검색 설정을 바꾸지 않고 데이터 쪽에서 해소됐다.

## 표 머리말을 채택하지 않은 이유

PR #88 리뷰에서 표 청크에도 기관명·사업명을 붙이자는 제안이 있었다. 표 청크 12,892개 중 기관명이
텍스트에 있는 것은 360개(3%)뿐이어서 지적은 사실이었다. 붙인 뒤 100%가 됐다.

리뷰에서 함께 제시된 두 축으로 측정했다.

**(1) 기관명 언급 질문에서 검색이 개선되는가 — 그렇다**

정답 문서 검색이 3.31에서 3.69로 올라 4세트 중 가장 높았다. Q01~Q04가 모두 5/5가 됐다.

**(2) 문서 안에서 구분이 흐려지는가 — 그렇다**

표의 `top_k` 점유가 2.4에서 3.8로 늘고, 키워드 적중률이 74.4%에서 48.7%로 떨어졌다. 기존 청크(60.3%)보다 낮다.

```
Q01   정답문서 3/5 -> 5/5   키워드 3.0 -> 0.0
Q05   정답문서 1/5 -> 0/5   키워드 6.0 -> 0.0
```

문서는 맞게 찾지만 그 안에서 엉뚱한 표가 올라온다. 한 문서의 표 전부에 같은 문구가 붙어 문서 간 구분은
좋아지고 문서 내 구분이 무너진 것이다. 짧은 표일수록 40자가 넘는 머리말이 실제 내용을 덮는다.

기대했던 Q07(다문서 비교)도 4.0에서 2.0으로 떨어졌다.

따라서 채택하지 않고 `use_table_headline: false`로 둔다. 다만 문서 식별력이 오르는 것은 분명하므로,
메타데이터 필터나 하이브리드 검색 쪽에서 활용할 여지는 남는다.

## 결론

**추출 + 절 제목**을 채택한다.

```yaml
chunking:
  use_section_titles: true       # 채택
  use_table_headline: false      # 기각
  max_section_title_length: 40
```

## 알려진 한계

- 본문 청크 5,333개 중 절 제목이 붙은 것은 2,240개(42%)다. 표지·목차처럼 제목이 없는 절이 있고,
  제목을 표가 아니라 일반 문단으로 만든 문서(`doc_003` 등)도 있다.
- 절 길이 편차가 크다(중앙값 282자, 최대 45,805자). 긴 절은 절 안에서 800자로 다시 나눈다.
- PDF 4건은 제목 표가 없어 기존 방식으로 청킹한다.
- Q08(근거 없음 문항)은 키워드 지표의 의미가 약해 판단에서 제외했다.
